# 国別設定とデータ条件に応じた設計

版：0.3 candidate。共通UX v1.0の採用前の設計規則。設計用`country-profile.json`はschema 0.1の記入用台帳であり、実行時の`data/dashboard.json`（schema 0.2）とは別物。実装・検証範囲は各版の記録で確認する。

## 1. 国別パッケージに持つ情報

| 分類 | 設定・確認するもの | 避けること |
|---|---|---|
| 利用業務 | 主な利用者、地域診断から計画までの作業、更新担当、公開対象 | すべての国に同じ職制・承認経路を置く |
| 地理 | 国ID、地域型、公式コード体系、行政階層、統計分類、境界版、有効期間、旧新対応表 | 名称だけの結合、行政と統計と支援対象の混同 |
| 言語と表示 | UI・資料の言語、翻訳語彙、日時・数値・通貨・単位、必要な文字方向 | ドミ共のスペイン語や金額単位を残す |
| 計画制度 | 計画の種類、担当主体、対象階層、期間、章構成、様式、公開・承認根拠 | PMD/CDM/CDPやNPA/LGDP等を他国へ一律転用する |
| データ | 指標辞書、資料・原表、観測期間、対象範囲、頻度、粒度、定義、変換方法 | 取得日を統計年として表示する |
| 機能 | 採用モジュール、データによる代替表示、出力形式、保存・復元、認証 | 未取得を理由に予告なく機能を消す |
| 運用 | 保守主体、出典利用条件、公開範囲、更新確認周期、公開先、費用・回線条件 | DDPTのホスト、認証、解析ID、資格情報のコピー |

行政階層は固定長の配列として使い切らず、地域型と所属関係を設定できる構造にする。独立市のように同じ階層でも型が異なる地域、飛び地、境界改編、コード変更、統計上のみの区分を表現できるようにする。

分析の基本単位は、その国の法制度で計画策定を担う地方政府と計画対象区域から決める。複数の法定階層、州法、条件付き義務を表現し、街区・集落等の統計上の最小区分と分ける。国勢調査の全数／標本、実査／補正、個人／世帯、詳細公表年・版を指標単位で確認し、計画の要求に足りない分野を省庁資料で補う。手順と調査台帳は[PLANNING_CENSUS_METHOD.md](PLANNING_CENSUS_METHOD.md)を参照。

## 2. 資料台帳と指標辞書

国ごとに少なくとも次を記録する。未確定欄は空欄の意味と担当を残し、推測で埋めない。

| 台帳 | 必須項目 |
|---|---|
| 出典 | `source_id`、機関、資料名、URL／原本参照、公開日、取得日、利用条件、原本hash、対象期間・地域、取得方法、担当 |
| 更新契約 | 元資料の公表頻度、こちらの確認頻度、想定される遅延、最終確認、次回確認、失敗時の再試行・通知・継続表示 |
| 地域 | `country_id`、`territory_id`、地域型、コード体系、公式コード、名称と別名、親・統計分類、境界版、有効期間、出典 |
| 指標 | `indicator_id`、ラベル、定義版、単位、母集団、分子・分母、実数／率／構成、集計方法、比較可能条件、出典 |
| 観測値 | 地域、指標、期間、細分類、値またはnull、数値状態、測定・推定の別、出典箇所、境界版、データ版 |
| 計画・資料 | 資料ID、国別種別、地域同定の根拠、原文の対象期間、資料URL・原本、取得状態、公式状態と根拠、確認済み本文・数値の箇所、出力形式・必要権限 |
| 変換記録 | 原資料版、変換処理版、結合方法、除外理由、未結合一覧、照合結果、生成日、担当 |

観測値の状態は`observed / missing / not_applicable / suppressed`を区別する。推定値を使う場合は別の`measurement_method`と方法・不確実性を示す。数値の有無、証拠の確認、取得処理の状態を１つの「なし」へ潰さない。実行時の許容値は[実装契約](IMPLEMENTATION_CONTRACT.md)に従う。計画資料の取得進捗は単一の`documents[].availability`で表し、別の抽出状態フィールドを重ねない。公式状態・内容の根拠は[計画資料データ契約](PLANNING_DATA_CONTRACT.md)に従って別に持つ。

## 3. 利用できる情報に応じた表示規則

機能の判定単位は**指標×地域×期間×境界版**を基本とする。国全体に一つの「データあり」フラグを立てても、地方の表示可否は判定できない。

| 条件 | 提供する表示・機能 | 追加条件／制約 |
|---|---|---|
| 比較可能な複数時点がある | 推移、同期間比較、増減 | 定義・境界・母集団を照合。断絶は線を切るか明示する |
| １時点だけある | KPI、構成、地域間比較 | 期間は固定表示。存在しない年や増減を作らない |
| 地方値があり境界結合も検証済み | 地図、表、順位、図 | 未結合件数と対象版を記録する |
| 地方値はあるが境界がない | 検索、一覧、棒グラフ、資料 | 地図機能は該当粒度で未提供と表示。別粒度へ無言で変えない |
| 境界のみある | 位置図と数値欠測表示 | 地域を選べる状態を維持する |
| 全国値しかない | 全国の参考欄 | 地方の主図と分離。人口比按分で地方値を作らない |
| 男女別年齢階級が揃う | 人口ピラミッド | 原表の階級を使い、単位を明示する |
| 広い年齢区分だけある | 取得済み区分の表・比較図 | 重複区分や全体を網羅しない区分を100%構成にしない |
| 出典の画像しかない | 原図＋出典＋地域・年の説明 | 数値表を取得していなければ数値CSVや再計算を提供しない |
| 比率と分子・分母が揃う | 公式値または検証した再集計、pp差 | 同一母集団・期間・定義を確認する |
| 比率だけで分母がない | 原資料の比率、比較可能なら中央値 | 地域率の単純平均を全国率として出さない |
| 事業が複数地域にまたがる | 事業一覧・対象範囲 | 全国事業数は一意IDで数え、地域別件数の合計との差を説明する |
| 計画は参照リンクのみ | 参照先と収録状態 | 本文抽出・公式承認を済ませたように示さない |
| 計画・財政資料が未取得 | 取得済み根拠と補完欄。草案出力は採用時に提供 | 「計画なし」「予算ゼロ」としない |
| AI生成の根拠・提供条件が不足 | 取得済み図表と手作業用の整理欄 | 生成の未提供理由を示し、計画作業を続けられるようにする |

率の集計は対象範囲が同じ分子の合計÷分母の合計を原則とし、定義により集計不可の場合は再集計しない。件数も重複・未配属・地理範囲を確認する。公式全国値と地方合計の差は照合項目であり、無根拠な架空地域への割り当てで一致させない。

## 4. 頻度・新旧・境界変更

- **観測期間、資料公開日、取得日、検証日、サイト反映日を分ける。**「最終更新」だけで統計の新しさを表現しない。
- 年次統計、国勢調査、月次行政記録、随時の計画資料は別の更新契約にする。共通の毎日更新で資料の鮮度を装わない。
- 単一指標の地域比較は、原則同じ期間・定義・境界の比較集合を使う。地域ごとの最新値を混在させる場合は別モードとして明示し、通常の同年順位と区別する。
- 複数分野の地域プロフィールでは年が異なり得る。図ごとに年を示し、全体の確認日を各値の年と混同しない。
- 境界改編は旧新コード・有効期間・対応関係を持つ。比較可能な公式再集計等がなければ、境界をまたぐ増減率を出さない。
- 定義が変わった場合は指標の定義版を更新し、過去値を黙って連続系列へつながない。
- 更新は取得→正規化→検証→候補版→反映→公開確認の順に行う。取得失敗時は最後に検証した版を保持し、更新停止・基準年・失敗の状態を示す。
- 公表周期が不明なら「不明」を記録し、担当者と確認予定を決める。根拠のない日次・月次の約束を置かない。

## 5. 機能の採用判断とソフトウェアの境界

各モジュール・図表に、`実装／条件付き実装／代替／保留`、根拠、利用可能範囲、制限理由、再検討条件、責任者を付ける。機能の導入順は現地業務と情報の価値で決め、DDPTにあるという理由だけでは増やさない。

参照テンプレートと国別成果は次の責務で分ける。任意機能の実装可否は[実装契約](IMPLEMENTATION_CONTRACT.md)と利用するcommitで確認する。

```text
テンプレート scaffold/site/   地域選択・URL・ページ表示・取得操作
テンプレート lib/             初期収集、データ検証、サイト生成
テンプレート tests/           欠測・選択・資料等の共通回帰検証
国別案件 data/dashboard.json  地域・統計・資料、任意のplanning設定
国別案件 adapters/            source別の取得・結合・正規化を案件で追加
国別案件 raw/、evidence/      原本、照合・不足・検証・採用判断の記録
国別案件 HANDOFF.md           参照版、最終成功版、再実行・再開手順
```

DDPTの既存実装との対応を保ち、新しいフレームワークへの全面書換えを前提にしない。国別成果は別ディレクトリへ生成し、一国の値をテンプレート本体へ混ぜない。国別リポジトリや公開先を作るかは現在の依頼範囲と保守責任・権限で決定する。

共通コア・国別設定・アダプター・データの版を別に記録する。共通改善は変更点と互換性を提示し、各国の代表試験を通した版だけ取り込む。一国の修正を全世界へ同時に配備しない。

## 6. 最初の適応検証

実データが比較的揃う地域と不足する地域を選び、以下を確認する。

1. 同じ地域選択・画面移動・資料取得の操作が成立する。
2. データ差に応じて図表が変わり、未取得の値が作られない。
3. 原資料の粒度・年・境界・母集団が、画面と出力から説明できる。
4. 更新担当が次の資料を追加し、失敗時には前の版へ戻せる。
5. 対応できない機能は理由と代替作業が分かる。

２例での成功は全世界への適用保証ではない。次の国で新しい制度・データ条件が見つかったら、国別差分として表現できるか、共通仕様の改訂が必要かを判断する。

## 7. 計画・資料をその国の制度と情報に合わせる

国名だけで始めた場合も、AIが公式の制度資料と実際の公開資料を調べ、次の観点を開始シートへ埋める。資料探索の区分と画面構成は同一ではない。計画・予算／財政・実施報告・公式評価の４観点を確認し、対象外や未公開にも根拠を残すが、４つのカード・ページ・同一章構成を必須にしない。その他の参考資料も利用できる。SISMAP、LGDPの章、５年周期、共通の達成点数を国の既定値にしない。

| 判断 | 国別に確認・記録する内容 | 表示・統合への反映 |
|---|---|---|
| 制度と業務 | 正式名称、対象階層、担当機関、計画周期・会計年度、法令・手引きの版と箇所 | 根拠のある名称・対象・期間を使い、章・尺度・承認経路は一律に置かない |
| 資料ごとの提供条件 | 原本URL、形式、公開頻度、対象地域・期間、利用条件、認証、取得・抽出方法 | source別アダプターを実装し、取得可能な優先資料は本文まで取得・照合する |
| 地域同定 | 照合した内部地域ID、国、地域型、コード体系、公式コード、境界版、適用期間と根拠 | `territory_match.territory_id`を文書の対象IDと一致させる。公式コードが双方nullでも別地域を同一化せず、同名・旧境界を曖昧結合しない |
| 取得状態 | リンク確認、本文取得、抽出、内容確認、未取得・取得失敗等 | `availability`に記録。取得しただけでは内容・承認を確認済みにしない |
| 公式状態 | 現地の状態名・定義、権限のある主体、根拠資料・箇所・確認日 | `official_status`と`official_evidence`を使う。根拠なしは未確認 |
| 本文・結果 | 要約・優先課題・目標、予算・収支・実施結果・評価の原文、定義・単位・対象・期間・尺度 | 内容確認した資料の`content`・`findings`へ変換。評価点・執行率・達成率を別に扱う |
| 画面と出力 | 採用区分・名称・順序、地図の意味、必要な出力と代替、既存投資・財政への接続 | 原資料を探す→地域を選ぶ→内容を確認→取得する経路を維持 |

設計用profileは判断と未定事項の台帳である。実行時には[計画資料データ契約](PLANNING_DATA_CONTRACT.md)に従い、`data/dashboard.json`の任意の`planning`設定と`documents`へ変換する。datasetのschemaは`"0.2"`を維持し、共通UX candidate 0.3や設計profile schema 0.1と混同しない。設定を省略した旧データの動作と、実装済みの出力を保つ。

`planning.sections`で採用した区分を並べ替えても、未掲載区分の取得済み資料を消さない。`planning.outputs`の省略は従来のMarkdown・HTML・根拠CSVを保つ意味で、空配列は提供しないという明示判断になる。後者は`purpose`等と案件記録に理由・原資料取得等の代替を示す。Word・PDF・AI生成の採用は国別に判断する。

地図は既定で資料収録状況を示す。`official_status`モードを採用するなら区分・資料の正確な対象期間・状態定義が必要で、根拠のない状態や相反する状態は未確認にする。計画・会計年度の`target_period`を統計の`period`選択で代用しない。古い計画の地域範囲は当時の台帳で説明し、現行境界への変換を根拠なく行わない。

原資料がない場合は取得済みの根拠、補完欄、原資料への経路等で作業できる代替を完成させる。`gaps`には該当地域・資料、試した方法、制約と次の行動を残す。更新時は候補版を検証してから置き換え、失敗した候補で最後の正常版を壊さない。`planning.update`は元資料更新の状態であり、サイト生成・配備の状態は別記録とする。担当と頻度が未定ならそのまま記録し、再実行コマンドと再開点を引き継ぐ。
