# 世界国勢調査データベース：OSS機能要件

制定：2026-09-14。状態：設計要件として採用。世界国勢調査DBとしての実装・実データ検証は未実施。

## 1. 採用方針

世界中の研究者・政府が利用、自営、改修、再利用できるOSSの共通データ基盤を目指す。既存サービスとの機能重複は除外理由にしない。IPUMS、IHGIS、REDATAM、Eurostat等で有用な検索・集計・取得・説明・地理機能は標準要件として採用する。新規性より利用者の業務、信頼性、再現性、運用可能性を優先する。

機能の採用と、既存コード・データの再利用は別に判断する。独自実装、互換接続、条件に適合するOSS部品の再利用を選べるようにする。既存DBにあるという理由だけで機能を後回しにしない。

本書は世界国勢調査DBの設計であり、現在のDDPTテンプレート0.4.0／dataset schema 0.2の実装完了や変更を意味しない。国別ダッシュボードの共通UX仕様v1.0採用とも区別する。

## 2. 収録する情報

| 区分 | 採用する内容 |
|---|---|
| 調査・資料台帳 | 国・地域、調査名・年・実査期間、公表段階、実施機関、報告書、調査票、変数辞書、原表・脚注、URL、取得日、原本ハッシュ、利用条件 |
| 基本統計 | 人口・年齢・性別、世帯・家族、教育・就学・識字、就業・職業・産業、移住、住宅、水・衛生・電力・通信。各国の項目と原分類を保持 |
| 国別の追加項目 | 障害・生活機能、出生・死亡、言語等、調査に存在し公開利用できる項目。質問文・対象・分類・秘匿を保持し、全世界共通の必須値にはしない |
| 方法・品質 | 全数・標本・登録ベース・複合方式、通常居住／現在人口、ウェイト、分母、推計・補完方法、未調査地域、事後調査、誤差・信頼区間、秘匿・丸め・摂動、公式訂正 |
| 地域 | 公式コードと体系、現地語・別名、行政区・統計区・都市圏・格子の区別、親子関係、有効期間、境界の出所と版、分割・合併・改称、対応表と根拠 |
| 補完情報 | 農業センサス、登録統計、貧困、難民・国内避難民、食料不安、施設・市場、人口格子、災害・環境。国勢調査とは情報源・方法・対象を分けて接続 |

国際共通指標への対応と原定義の保存を両立する。全国の率を地方に埋めない。同じ原資料を複数機関から取得しても、独立した観測や別人口として重複加算しない。世界の調査台帳、数値の収録範囲、境界まで照合した範囲を別々に示す。

## 4. 計算・地理・公開の共通条件

- 年齢別人口と障害者総数の別表から、年齢別障害者数を作らない。F03は既存の結合分布の範囲を基本とし、F22の個票集計と区別する。
- 加算には排他的・網羅的な範囲、同年・同定義・同単位・同境界版、必要な原表・ウェイトを確認する。率平均を親の率にせず、分母を保持する。中央値等の非加算指標を根拠なく再集計しない。
- 上下位表の差を検出・説明する。丸め・秘匿・摂動・補正のある公表値を合計合わせで上書きしない。欠けた構成地域から部分合計を全体値として出さない。
- 公式公表値、抽出値、標本・小地域推計、格子集計、将来予測を区別する。値・方法・境界・年の選択を利用者に示す。
- 地域対応表があるだけで人口配分可能とはしない。人口や面積の根拠を確認する。旧コードの再利用、分割・合併、複数親、統計区と行政区、異なる境界の主張を保存し、名称だけで統合しない。
- 公開不可・秘匿は欠測・ゼロと別に扱い、秘匿値を他表との差から復元する機能を作らない。
- 原本保存・再配布・派生成果の公開は資料別の条件に従う。同梱できない原本のある再現パッケージには、許可されたメタ情報、取得条件・手順、版識別子、必要権限を示す。
- API仕様・版・変更履歴・廃止予定・上限・再試行方法を公開。外部障害で正常な保存データを失わず、認証情報をコード・サンプル・抽出成果に含めない。

## 5. OSSとして提供するもの

1. 収集・検証・抽出・API・画面のコード、スキーマ、仕様、テスト、導入・更新・バックアップ手順。
2. 特定の有料クラウドやAI契約がなくても基本機能を動かせる構成。AIは任意部品とし、確定済み変換を通常のプログラムで再実行する。
3. 再配布可能な小規模データと合成テスト資料。合成資料は明示し、実国の統計として表示しない。
4. アダプター作成手順、期待出力、実行例、互換性検証、翻訳手順、貢献・レビュー規則。
5. コード・依存物のライセンス・著作権表示、データ・境界・文書ごとの利用条件、出典、配布可能範囲。
6. 公開コードから再構築できるリリース、版を固定した成果、変更履歴、課題・訂正窓口。運用主体と保守担当の明示。

OSSはコードの閲覧に加え、利用・改変・再配布を許すライセンスを整備する。具体的なOSSライセンスは公開準備で決定する。本書の追加はライセンス付与でもPrivateリポジトリのPublic化でもない。

コードのOSS化で第三者の統計・境界・個票が自動的に再配布可能になるわけではない。IPUMS IHGISは再配布条件を持つ。既存コードもその依存物を含む条件を確認する。原資料から独自構築する場合は原資料の条件を記録する。

## 6. DDPTとの接続

DBは研究用の小地域・独自範囲にも対応する独立した基盤とする。DDPTはその利用先の一つであり、研究機能を通常画面へ一括追加しない。

[計画と国勢調査の手順](PLANNING_CENSUS_METHOD.md)、[共通操作契約](02_COMMON_SPEC.md)、[国別データ適応](03_COUNTRY_AND_DATA.md)を維持する。位置図・上位選択・内部比較の役割を保ち、上位を再選択したら下位を解除して上位全体へ切り替える。小地域の収録だけを理由に、基礎自治体での通常の細分停止を変更しない。

接続時は国・地域コード・境界版・指標定義・データ版を固定し、現行schemaとの対応と旧データ・URL・保存・出力の互換性を検証する。国別の制度・出力形式を世界共通へ固定しない。

| 探索・抽出 | 粒度が異なる資料、存在しない属性組合せ、重複依頼、大きい抽出・中断再開の結果と状態 |

| 再現・更新 | 同じ原本・条件・処理版からの再生成。上流の訂正・取得障害・旧版の再取得 |
| 公開・自営 | 利用条件の異なる資料を含む出力。新規環境で導入・復元・API・取得物を確認 |
| 利用者 | 研究者の多国比較と自治体の基礎診断。キーボード、多言語、低速回線、全表出力 |

記録にはF番号、対象commit、データ・境界・処理版、日付、環境、結果と未実施を残す。既存テンプレートのテスト合格を新DBの合格と報告しない。
