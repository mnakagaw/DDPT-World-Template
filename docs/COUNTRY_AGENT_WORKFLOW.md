# 国名だけを受け取ったAIの国別作業手順

この手順は、新しい案件でDDPT-World-Templateを参照し、その国の公開資料を取得して動作するサイトを作るためのもの。利用者の国名は作業開始に十分な入力として扱い、AIが開始シートを埋める。長い質問票を返して作業を止めない。[Census Dashboard Kitの国別制作・独立監査から得た完成工程](research/census-dashboard-kit-country-lessons-2026-09-17.md)も適用し、初期生成や最初の取得しやすい資料を完成と扱わない。

国別出力のルートへコピーされたこの文書を読む場合、`scripts/`・`templates/`と補助資料への参照は、記録したテンプレートclone内で解決する。`HANDOFF.md`にその絶対パス・GitHub URL・参照commitを残す。見つからなければ同じcommitのリポジトリを読み直し、国別データを初期化しない。

## 1. 既存の依頼と作業場所を確認する

- 既存の国、言語、利用目的、保存先、公開依頼、利用可能な資料・資産を優先する。
- テンプレートの認証済みcloneと参照commit、対象案件の既存ファイル・変更を確認する。テンプレート、DDPT、他国の作業中成果を国別出力先にしない。
- 新規出力先が未指定なら、案件ワークスペース内の未使用ディレクトリを選ぶ。`create-country.mjs`は新規作成用で、再開時の上書き手段ではない。
- 国名は原入力を残してISO国IDへ正規化する。同名・通称が複数の国を指し、選択によって資料や制度が変わる場合だけ短く確認する。

AIが`templates/COUNTRY_START.md`を案件へコピーして記入する。初期の既定値は次のとおりで、調査結果により更新する。

| 未指定項目 | 作業を進める既定値 |
|---|---|
| 利用目的 | 地方の計画担当者による地域診断と資料取得、中央・広域担当者による地域比較 |
| 納品範囲 | ローカルサイト・データ・採用出力・検証記録。別リポジトリ作成や外部公開は現在の依頼範囲に従う |
| 画面言語 | 取得した公式資料と利用者指示を確認して暫定設定。CLIの初期localeを現地要件確認済みと扱わない |
| 地理粒度 | 計画法・自治体法等で計画を作る責任を持つ地方政府と計画区域を先に特定し、その単位の統計を優先。街区・集落は自治体内診断の補助として扱う |
| 時点 | 統計は同年比較が成立する集合を使う。計画期間・会計年度・四半期・評価基準日は原資料の表記で別管理 |
| 機能 | 地域診断・テーマ比較・計画資料への経路を中心に、投資・要求・文章生成・保存・出力を根拠に応じて採用 |
| 更新・運用担当 | 未定と記録。勝手に担当者、通知先、更新頻度を確約しない |

### 制度と国勢調査の接続を先に設定する

[PLANNING_CENSUS_METHOD.md](PLANNING_CENSUS_METHOD.md)を読み、[調査台帳](../templates/PLANNING_CENSUS_AUDIT.md)を案件へコピーする。法令名・制定年・参照改正年・所管／作成／承認主体・計画類型・法定対象区域を調べる。ADM2や取得可能な最小粒度を自治体として固定しない。州法・人口条件・複数階層の計画義務を区別する。

最新調査年と使える詳細統計年、公表目録と実数値取得、全数と標本・補正を別記録にする。国勢調査で地域診断の基礎を作り、法定診断項目と地域課題に不足するテーマから国内省庁資料へ探索を広げる。[ラテンアメリカ20か国調査](research/latin-america-2026/REPORT.md)は探索の出発点であり、案件時点の法令・公表版・地域照合の再確認を省略する根拠ではない。

計画主体の確定と探索・分析範囲の設定を分ける。世界・大陸・広域・全国を分析に使う場合は、構成地域・分類出典・比較可能性を記録する。基礎自治体を国別に確認して通常の細分停止点を定め、研究資料の街区・集落の記載から下位UIを自動追加しない。研究REPORT・台帳は調査時点の記録として保持する。

## 2. 初期収集を実行する

テンプレートのルートから実行する。出力パスと国名は実案件へ置き換える。

```sh
node scripts/create-country.mjs --country "ウガンダ" --out ../uganda-dashboard
```

生成された`data/dashboard.json`、`raw/`、検証結果、`gaps`を読む。WDI全国値とgeoBoundaries ADM1の取得可否を確認し、取得失敗を欠測ゼロや未公開に読み替えない。国の正規化に失敗した場合は公式名称・ISO IDを調べて入力を直し、取得障害なら原因を記録して取得可能な別資料の作業へ進む。

`evidence/SOURCE_PREFLIGHT.md`と`.json`を読む。国別の事前調査があれば国勢調査、計画法・手引き、計画資料、境界・コードの所在を起点にし、リンク・最新版・内容を再確認する。事前調査がなければ同じ5区分の所在調査を最初に行い、案件の台帳とテンプレート側registryへ再利用可能な結果を残す。国際共通sourceはcountry availabilityを調べ、国勢調査・標本調査・人道観測・格子推計の違いを保持する。[台帳と保存方法](COMMON_DATA_AND_SOURCE_REGISTRY.md)を参照する。

**この工程は初期生成であり、完了地点ではない。直ちに次の公式資料調査へ進む。**

## 3. 国内の公式資料を調べて取得する

次の分野を並行して調べ、取得・統合は依存関係に沿って進める。現地語と英語の名称も使う。機関名、現行制度、リンク、資料の時点はその案件で確認する。

| 分野 | 最初に確認する一次資料 | 残す成果 |
|---|---|---|
| 地域・コード | 統計局／国勢調査の地域コード表、行政機関の区分・境界・改編資料 | 地域台帳、版、有効期間、コード対応表、未結合一覧 |
| 地方統計 | 国勢調査、公式統計ポータル、地域別統計書、行政統計 | 人口・サービス・生計等の取得可能な地方値、定義、年、分子分母、出典箇所 |
| 計画制度・資料 | 国・地方の計画機関、法定手引き、地方計画、公式様式 | 対象階層、計画期間、担当主体、資料リンク・原本、取得状態、承認根拠の別記録 |
| 予算・公共投資 | 財務機関、公開予算書、地方財政、事業台帳 | 期間・金額単位・予算／実績・事業ID・対象地域と重複方針 |
| 実施報告・公式評価 | 地方政府・所管機関の実施報告、監査・評価の公開資料、評価方法 | 実施結果、評価主体、定義・尺度・対象・期間。評価点と執行率・計画達成率の区別 |
| 住民要求・参加 | 公開された協議記録、提案台帳、制度手引き | 出典付きの要求・参加・決定の区別。未公開なら理由と代替作業 |

計画策定単位と内部分析単位を分ける。例えばDistrict計画では、District全体に加えて内部格差を診断するSubcounty等の統計・境界を調べる。細かな統計があることだけで、その地域を法定計画主体に変更しない。

公開データがAPIや表で提供されるなら、その取得方法を優先する。公式Excel・PDF・原図しかない場合も、利用可能な表計算・PDF・文書のツールと該当スキルで抽出し、元の表・ページと照合する。内容を取得できないリンクを「本文確認済み」と記録しない。

同じ指標・期間・定義・地理範囲で比較できる国内公式値がある場合は、国内の一次資料を優先する。国際データの方が新しい等の差は隠さず、別出典・別系列として保持して採用理由を記す。国内地方値とWDI全国値を定義照合なしに足し合わせない。

公開されていて取得できる優先資料は実際に取得し、[SOURCE_ADAPTER_GUIDE.md](SOURCE_ADAPTER_GUIDE.md)に従ってアダプターを追加する。資料の候補リンクを列挙しただけで国別収集を完了にしない。

統計局・国勢調査等の公式catalogueを確認した場合は、期待する全資料を `evidence/SOURCE_RESOURCE_INVENTORY.json` 等へ列挙する。各資料を `integrated / acquired_not_adopted / unavailable / restricted / failed_with_evidence / duplicate / superseded / incompatible / excluded` のいずれかへ処置し、理由と証拠を残す。代表地域の1冊や最初に取得できた全国表だけでcatalogue全体を閉じない。所在、取得、内容確認、地理照合、採用は別の状態にする。`all_tables_checked` や `all_numeric_fields_decided` は原本のsheet／table／field集合と台帳を機械照合して導出し、`remaining fields` 等のcatch-all一行で真にしない。

計画・予算／財政・実施報告・公式評価の４観点は調査台帳に残し、対象外や未公開の場合も理由を記す。これらを４つの必須ページや同じカードにする指示ではない。国別の対象階層、制度名、計画周期、会計年度、章立て、状態・評価の定義を根拠で確認し、資料ごとの形式・公開範囲・利用条件・公表周期・取得方法を記録する。SISMAPや特定国の計画章・５年周期を既定値にしない。

## 4. 地方データを統合し、機能を適応する

統合前に[ウガンダ2案件の教訓](research/uganda-lessons-2026-09-14.md)のUL01～UL05と[国別制作・独立監査の教訓](research/census-dashboard-kit-country-lessons-2026-09-17.md)を適用する。画面へ載せやすい数項目だけで収集を終えず、確認した原資料の全表・全数値列を `evidence/SOURCE_TABLE_INVENTORY.json` または `evidence/INDICATOR_INVENTORY.csv` 等へ記録する。原指標・分子分母・重複・補助列と採用／非採用・理由を区別する。元fieldの定義・母集団・単位と表示indicatorの意味を明示的に対応させ、名称の類似だけで結合しない。採用指標数、原列数、観測件数、国勢調査全体の範囲を同じ数として説明しない。

一括表で不足した優先テーマは全国報告書の本文・付表、地域統計書、定義・調査票へ探索を広げる。各資料の確認範囲、未取得、次の取得方法を残す。PDFの抽出は可視原頁、重複行、表の継続、単位と照合し、抽出テキストだけで採用しない。公開されていない原資料や意味を確定できない項目を無限に待たず、理由と代替を記して他の取得・統合を進める。

取得・結合・比較可能な範囲を指標×年×地域型×母集団ごとに記録する。登録人口と国勢調査人口、区域人口と身分類型、重複年齢群、人数と率を無言で置き換えない。全国と構成地域合計の差は、別掲の原記録・定義・丸め等で説明し、未説明差は残す。全項目の棚卸しは、DDPT画面へ全項目・全階層を一度に並べる指示ではない。

1. 地域の名前より先に、コード体系・公式コードの根拠・境界版・親子関係を照合する。geoBoundariesのshapeIDはprovider IDとして扱う。
2. 同名地域、独立市、境界改編、複数地域事業を検査し、曖昧な結合は未結合として残す。
3. アダプターで`schema_version: "0.2"`へ正規化し、出典・原本hash・抽出位置・変換方法を保存する。
4. 既存データと統合する際はIDと観測キーの重複、期間、単位、地域数、カバー率を確認する。全国値を地方へ補完しない。
5. `実装／条件付き実装／代替／保留`を指標・地域・期間・境界版ごとに決める。地図なしなら一覧、時系列なしなら実在する時点、根拠不足なら資料と補完欄を提供する。
6. DDPTの二つの診断入口、選択地域の連動、出典と欠測、計画資料への到達を保つ。粒度差を理由に首都へ戻したり、別の追加操作を必須にしたりしない。
7. 地域階層は国別の`parent_id`で定義する。市・県を選んだ後に、同じ所属先の上位をドロップダウンから再選択したら、市・県以下を解除して上位全体へ更新する。所属先の表示と分析対象の選択を区別し、指標・年を保持する。階層の追加自体は集計の根拠ではなく、親の観測は公式値または検証済みの再集計値を明示的に登録する。
8. 上部の地域選択・基本情報・位置図を保ったまま、各指標の下部へ内部比較の地図と全件表を追加する。全国を含む選択範囲ごとに、構成地域の全体台帳、粒度、同年・同定義・同母集団・同単位・同境界版を確認する。内部比較の注目変更は分析対象の選択と分ける。欠測・境界不足でも親の診断を保持し、基礎自治体の下へ細分しない。

内部比較は[分析データ契約](ANALYSIS_DATA_CONTRACT.md)へ次のように対応付ける。

- 任意の`analysis`を追加する場合は`kind: "country"`、`terminal_territory_ids`、`comparisons`を用意する。明示比較に親ID・構成ID全件・説明・所属根拠のsource IDを登録する。旧データで直接の子を使う既定と、市・自治体型等で停止する既定が、その国で妥当か確認する。
- 定義・単位・母集団・方法が違う観測は、元のmetadataと値・比較不可理由を保持する。概念の異なる国際／国内系列を別指標IDにし、率の平均で親を埋めない。色尺度は選択内の再計算か根拠のある固定閾値かを明示する。
- 診断Markdown、地図・取得済み推移図・全件表を含むHTML、選択年の全指標・全比較行CSVを提供する。Markdownは編集用の根拠資料で、合意・公式承認済みの計画書として扱わない。計画ページの出力設定は独立して保持する。
- 世界入口から接続する依頼がある場合は[世界アダプター](WORLD_ADAPTER.md)の別datasetと`country_sites`を使う。国ID・対象ID・URLと明示した`indicator_map`を照合し、未対応指標や無効年を移動先でどう扱うか確認する。国版から世界への専用戻り設定を実装済みと想定せず、ブラウザーの戻るとURL復元を確認する。

計画・資料は[PLANNING_DATA_CONTRACT.md](PLANNING_DATA_CONTRACT.md)に従い、次を順に行う。

1. 原本を保存し、source別に抽出を再実行できる処理を実装する。計画の優先課題・目標、財政・実施結果・評価を載せる場合は、頁・表・定義・尺度・対象・期間を原本と照合してから`content`／`findings`へ追加する。数値がない所見は根拠のある文章として扱い、数値を作らない。
2. `territory_match`で照合した内部`territory_id`、国・地域型・コード体系・公式コード・境界版と有効期間の根拠を確認する。内部IDを文書の対象IDと一致させ、公式コードが双方nullでも別地域を同一化しない。同名地域や古い計画を現行地域へ強制結合しない。計画・会計年度の`target_period`は統計の選択年から独立させる。
3. `availability`でリンク確認・本文取得・抽出・内容確認を区別し、公式状態は別の`official_status`と`official_evidence`へ記録する。旧データの根拠なしの状態を確認済みに変更しない。
4. AIが設計用profileへ採用判断を残し、runtimeでは`dataset.planning`へ反映する。資料区分の名称・順序、概要、地図の意味、出力、既存投資・財政への関連リンクを選ぶ。区分外の資料にも到達可能にし、出力なしなら原資料取得等の代替を説明する。公式状態の地図には区分・資料の正確な期間・国別状態定義・証拠が必要で、欠落・矛盾は未確認とする。

設計profileのschema 0.1、datasetのschema 0.2、共通UX 0.4 candidateは別の版である。仕様への記載を実装済みと想定せず、利用するcommitの検証器・生成器と実際の出力を確認する。

地方値・資料がないと判断する前に、公式ポータル、国勢調査表、地域統計書、計画／予算資料の確認結果を残す。「初期アダプターが未対応」は「資料が存在しない」ではない。

## 5. 再構築して実物を検証する

全国の展開前に、資料が揃う自治体、同名の別行政型、資料・図形不足の自治体など、その国で異なる条件の代表例を選ぶ。選択→診断→比較→資料→採用出力を一度通し、操作と情報配置をDDPT参照・共通契約に照合する。次に同じ再実行処理を全対象へ展開し、全件の機械検査と例外の原典照合を組み合わせる。自治体ごとの手作業コピーで全国化しない。

[補助確認票](../templates/COUNTRY_LESSON_AUDIT.md)のUA01～UA12をAIが案件へ記入する。標準42シナリオと別集計にし、過去の合格を転記しない。計画基礎文書を採用した場合は、要件と原頁→章・表・必要欄→実取得物の対応を確認する。「様式はあるが記入待ち」と「様式そのものが不足」を分け、必要欄の不足を職員への注意書きだけで代替しない。章立てが一致しても正式準拠や承認済みと判断しない。

国別の通常画面は、選択地域について指標ごとの最新確認値と実際の年を表示できる。テーマ比較は、一指標・一地域型・一比較集合・一共通年へ地図、全件表、順位、比較CSVを揃える。これは世界・広域の混合基準年集計や研究用データベースから履歴を削除する指示ではない。過去観測・原本・変換記録は監査と更新のため保持する。

`latest`、`source reported`、`calculated`、`no gaps`等の表示はmetadataの自己申告だけで決めない。観測から地域・指標・系列ごとの最大確認年を再計算し、算出値は式・分子分母・被覆・変換履歴を示し、不足表示は実台帳から導出する。

指標拡充後は既存値・ID・出典・保存・URLの差分を確認する。追加項目の長いラベル・多数行でも図の文字と軸が読めるか、地域単位の実測転送量・初回表示・操作待ち・再試行を確認し、必要に応じて分割取得する。現地回線・実機未確認ならその限界を残す。

```sh
node scripts/build-country.mjs --project ../uganda-dashboard
node scripts/serve.mjs --dir ../uganda-dashboard/site --port 4173
```

ブラウザで`http://127.0.0.1:4173`を開き、データ契約の検証と画面・取得物の実操作を分けて記録する。検証エラーは修正し、警告は理由・影響・処置を判断する。READMEに記載した開発・build・previewコマンドも新しいclone相当の状態で実行し、追跡済みの公開distだけが動く状態を合格にしない。テストの期待件数は可能な限りデータから導出し、指標拡充後の古い固定値を残さない。

- データが比較的揃う地域と不足する地域で、選択→診断／比較→計画資料→採用出力を確認する。地域変更はselectorとURLの更新だけで完了とせず、loading終了後のtitle、heading、地図、指標、資料、download対象まで同じcanonical territory IDであることを確認する。
- 全国・同名地域・異なる行政型・未対応粒度、URL共有・再読込・戻る、絞り込み範囲を確認する。
- 必ず市・県を先に選んでから、その市・県と**同じSubregion／Region**をドロップダウンで選び直す。下位選択が解除され、見出し・地図・下部全指標・資料・出力対象が親全体へ一致することを、親の値がある場合とない場合で確かめる。初期状態から親を選ぶ試験だけで代用しない。
- 出力を実際に取得し、地域・期間・単位・代表値・出典・草案状態を画面と照合する。利用可能な形式のみを対象にする。
- Word／PDFを採用した場合は実ファイルを生成し、隔離されたrendererで全ページを確認する。`undefined`、空のテンプレート指示、切れ・重なり、言語混在、地域・値・年・出典の不一致を残さない。文書は選択地域の計画策定用診断資料であり、根拠のない政府公表物・承認済み計画・計画案として表示しない。
- 資料を持つ地域→持たない親／別地域で、古い資料・本文・評価が残らないことを確認する。区分の採用・非採用、旧形式データ、異なる資料期間、根拠のない公式状態、数値0と欠測、採用地図・出力・関連リンクをA27以降で検証する。
- 内部比較はA35以降で確認する。各指標の地図・全件表の対象と期間、全国での表示、基礎自治体での停止、クリックで分析対象・URL・資料・出力先が変わらないこと、診断3形式の全体値・内部全行・状態・出典の対応、印刷で全行を保持することを実物で確かめる。
- 対応する全言語で指標名、theme、notice、資料、downloadを確認し、意図した原語併記と未翻訳を分ける。狭い画面、文字拡大、キーボード、待機・失敗・再試行を[受入記録](../templates/ACCEPTANCE.md)に沿って確認する。
- 現地担当者による利用確認はAIのブラウザ試験と別に扱い、未実施なら残す。

## 6. 欠測台帳と再開点を保存する

次はAIが案件側へ作成・更新する記録で、CLIが自動作成済みと想定しない。生成器が同目的の資料を作る場合はその名称と場所を確認して再利用する。

| 記録 | 最低限の内容 |
|---|---|
| `evidence/SOURCES.md` | 実際に確認した機関・資料URL・時点・取得結果・選定理由・原本・アダプター・再実行方法。計画制度とsource別条件、公式状態・内容の根拠箇所 |
| `evidence/SOURCE_RESOURCE_INVENTORY.json` | 公式catalogueの期待資料、発見・取得・hash・統合件数、各資料の処置と根拠。全期待資料に処置が付いているか |
| `evidence/SOURCE_TABLE_INVENTORY.json` | 取得原本の全sheet・table・field、定義・単位・分母・粒度・期間、指標対応、非採用理由、再配布判断 |
| `evidence/THEME_COVERAGE.json` | 人口、教育、保健・栄養、水・衛生・住宅・エネルギー、生計・貧困・経済、アクセス・インフラ・環境の探索・統合・制約状態 |
| `evidence/CODE_CROSSWALK.csv` | provider ID、公式コード、コード体系、境界版、対応根拠、照合状態。未照合は空欄の意味を明記 |
| `evidence/GEOGRAPHY_REVIEW.md` | 階層別の地域数・図形数、未結合ID、境界版、URL同一性、図形なし表示、代用していないことの確認 |
| `evidence/INDICATOR_INVENTORY.csv` 等 | 確認した原資料の全項目、原位置、役割、採否と理由、原列と指標の対応。未確認資料を網羅済みとしない |
| `evidence/COUNTRY_LESSON_AUDIT.md` | 代表・例外地域、UA01～UA12の証拠・判定、採用する計画出力の要件と欄の対応。標準受入とは別集計 |
| `evidence/GAPS.md` | 分野・地域・期間、不足の種類、確認済み資料、試した取得方法、障害、次の具体的行動、担当／再確認条件 |
| `evidence/ACCEPTANCE.md` | 対象版、実データ、環境、各試験、証拠、合否、未実施 |
| `evidence/WORD_RENDER_CHECK.md` | Word採用時のファイル、対象地域、renderer、ページ数、全ページの可読性・内容・言語確認。未採用なら対象外理由 |
| `evidence/DELIVERY.md` または `.json` | 研究・地理・計画・地方統計・比較・出力・公開の閉鎖状態、制約、対象commit・データ版。自動gateがない版では人手判定と明記 |
| `evidence/INDEPENDENT_AUDIT.md` | 制作者と別の担当による原資料・データ・画面・操作・出力の監査、所見、未実施、`ACCEPT / REJECT / INCOMPLETE AUDIT` |
| `HANDOFF.md` | 完了工程、途中工程、各記録のパス、最後に成功したコマンド・データ版、次のコマンド、未解決事項、依頼済みの範囲 |

コンテキスト切替や中断前は`HANDOFF.md`へ作業途中の資料URL・原本・抽出位置・失敗内容も残す。再開時はその記録と現物を確認し、初期収集をやり直して公式地方データを消さない。

更新は原本取得→候補への変換→地域・期間・内容検証→正常版への反映→再構築の順とする。失敗候補で最後の正常データを置き換えない。元資料の停止理由、確認日時、最終成功日時を`planning.update`と台帳に記録し、生成・配備側の失敗は別記録へ残す。原本からの再実行と、新版の列・コード・定義・期間変更の確認方法を引き継ぐ。更新間隔や担当が不明なら未定として残し、勝手に運用を確約しない。

## 7. 完了を判断して報告する

初期生成だけで終了しない。優先する国内公式資料を調べ、取得可能な地方統計と計画資料を取り込み、地域作業と採用出力を実装・検証してから成果を報告する。全指標の網羅収集を約束する必要はないが、採用範囲・収録率・未収録範囲が説明できなければならない。

次が残る場合は、通常の完成として報告しない。公式catalogueに未処置資料がある、取得原本に未棚卸しの表・数値列がある、利用可能候補を発見したまま未統合・未処置である、選択可能階層の地理判断がない、親再選択で子の状態が残る、比較範囲・階層・地図・表・年が一致しない、親欠測を子や全国値で埋める、採用文書を実生成・renderしていない、適用する受入試験が未実施、公開依頼時にremote read-backと公開操作を確認していない。自動delivery gateを実装していない版では、人手の閉鎖表を残して自動合格を装わない。

必要な資料が公開されていない、アクセス権がない等の制約は、確認した根拠と代替機能、未完了の業務を明示する。制約下で提供できるローカル版を作成し、全国参考データと境界のみの状態を「地方計画版完成」と呼ばない。

制作者が完成候補を閉じた後、[独立完成監査票](../templates/INDEPENDENT_AUDIT.md)を使い、別のタスク・会話・担当が修正せずに実物を監査する。監査は `DELIVERY.json`、緑のtest、制作者の説明を単独証拠にせず、原資料から代表値、意味、年、地理、比較集合、計画資料、ブラウザ操作、取得物、render済み文書を追跡する。blockingまたはmajor findingが残る `REJECT`、必要確認が終わらない `INCOMPLETE AUDIT` の間は公開しない。制作者が実データ・コード・出力を修正してremediationを残した後、別監査を再実施し、`ACCEPT` で公開可能とする。

現在の依頼にGitHub作成・公開まで含まれる場合は、独立監査の `ACCEPT` 後に、その範囲の版・配備・公開後確認まで進める。国名だけで始めた案件ではローカル成果を既定とし、テンプレート本体のPrivate GitHub作成許可を別国リポジトリや公開サイトへの許可へ転用しない。単一の実行環境で別担当の監査を開始できない場合は、完成候補と監査用証拠を保存し、`INDEPENDENT AUDIT PENDING` として引き継ぐ。制作者自身の再確認を独立監査と呼ばない。
