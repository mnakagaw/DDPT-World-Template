# 0.2.1 上位地域の再選択と連動の検証

日付：2026-09-13。データschemaは0.2を維持する。前版の取得試験は[0.2記録](VALIDATION_v0.2.md)を参照し、今回の実行結果と混ぜない。

## 変更の根拠と対象

利用者は「ウガンダLGDPダッシュボード構築」の直近の議論を参照するよう依頼し、特に、市を選択後に上位をドロップダウンで選び直したら市を解除して上位全体を表示する操作を指定した。

- 市・県の所属先と、その上位全体を分析対象として選ぶ操作を区別する。同じ所属先を再選択しても実際のchangeが成立するUIを使う。
- `parent_id`から国別の階層をたどり、最後に明示選択した地域IDへ表示・URL・出力を揃える。指標・年は保持する。
- 親が未取得なら親自身の欠測を表示する。子の値の残留や、根拠のないその場の合算をしない。
- 同じ議論で指定されたブランドの全国初期表示、通常メニューでの条件保持、地図選択行の順位表内への自動表示も共通化する。

最新の別タスクの進捗や公開完了の有無は、本テンプレートの合格根拠にしない。[ウガンダの指示・記録](UGANDA_LESSONS.md)に参照時点を分けて記した。

## 検証対象

複数階層の操作には明示的な合成テスト国を使う。テスト用の値・境界は国別実データや初期収集器へ混入させない。以下を自動試験と実ブラウザー操作で照合する。

1. 市 → 同じSubregion全体、市 → 同じRegion全体、市 → 別Region、親全体 → 市。
2. 親の値がある場合と未取得の場合の見出し・全分野・地図・出力対象。
3. 上位再選択後の同一URLでの再読込、戻る、進む、通常メニュー移動。
4. ブラウザーの実際のドロップダウンで所属表示とWhole選択肢が異なり、同じ親を選び直せること。
5. ブランドで全国・既定条件へ戻ること、メニューで条件を保持すること。
6. 地図で選んだ順位表の行、検索による非表示、欠測の扱い、表内スクロール。

## 実行結果

`npm run check`成功（JavaScript 18モジュールとJSONテンプレート）、`npm test`は**47件成功・失敗0件**。親の再選択、子欄の解除、親の欠測、URL復元、同名でも別ID、階層が1段の場合、順位検索と表内スクロールを含む。国別プロファイルの共通仕様参照も0.2へ更新した。

EdgeとCodex内ブラウザーで、生成済みの同一合成データをローカル配信し、ネイティブselect操作と画面・URL・取得ファイルを照合した。選択関数の直接呼出しやDOMへの値注入を実ブラウザー試験の代用にしていない。
