# 計画制度から国勢調査・分野別資料へつなぐ方法

制定：2026-09-13。国別案件の調査・適応手順。実行テンプレート0.3.0／データschema 0.2を変更するものではない。

## 1. 完了させる業務

地方自治体が自国の制度に沿って計画を作成・見直しできるように、地域診断、分野比較、既存計画、住民要求、公共投資、計画草案の根拠をつなぐ。DDPTでの「地域診断→投資→需要→計画策定」を基準にする。国勢調査を基礎統計の第一候補にし、法定診断と地域の課題に不足する項目を国内の分野別資料で補う。

計画策定の対象は**計画法・自治体法・州法等により計画を作る責任を持つ地方政府と、その計画の対象区域**から決める。取得できる最小統計区分やADM2を先に選んで、それを自治体と呼ばない。複数の階層に義務がある場合は、計画の種類と主体を複数登録する。

例：エクアドルでは州・郡・農村教区のGADを区別する。ウルグアイでは自治体の管理計画と部門政府の土地利用計画を区別する。エルサルバドルでは44自治体と262地区を分ける。アルゼンチン・メキシコでは州法の確認が必要である。ブラジルのPlano Diretorには人口等の適用要件がある。[20か国の根拠付き比較](research/latin-america-2026/REPORT.md)を参照する。

## 2. 制度・機関の台帳を先に作る

AIが[調査台帳](../templates/PLANNING_CENSUS_AUDIT.md)を案件へコピーして埋める。調べられる項目のために利用者へ質問票を返さない。

| 台帳項目 | 記録内容 |
|---|---|
| 法令 | 原文名、番号、法／政令／規範／手引きの別、制定年、参照改正年、施行・廃止の根拠、条文・公式URL、確認日 |
| 適用 | 計画の正式名、義務／権限／推奨の別、対象地方政府、人口等の適用条件、特別自治、区域とコード版 |
| 主体 | 国家の制度所管、技術支援機関、地方の作成責任者、協議・承認主体を別欄で管理。旧称・承継日も記録 |
| 手続き | 必須章・診断項目・協議・公表・承認根拠、期間・見直し条件、提出様式と版 |
| 整合 | 上位計画、土地利用、複数年投資、年次予算、事業台帳との接続方法 |
| 証拠 | 確認済みの範囲、未確認の改正・条例・運用、次に取得する資料 |

法令の存在から各自治体の承認済み計画の存在を推定しない。計画の公開リンクの有無から法的義務の有無も判定しない。中央の支援機関を自治体の承認者として追加しない。

## 3. 国勢調査の利用可能範囲を確かめる

英語の探索語は **Population and Housing Census** を基本にし、現地語の名称も使う。公表目録、調査票、変数辞書、集計表、秘匿・標本・補正の方法、公式コード表を組にして取得する。

調査予定、実査実施、人口速報、確報、テーマ詳細、小地域表を別段階として記録する。最新調査年と、実際に採用する詳細統計年を別欄にする。公表日・取得日も統計年から分ける。新調査の人口だけが公表された場合、全テーマを新しい年に変更しない。

確認単位は**指標×統計年×公開地域単位×母集団×調査票種×公開版**とする。国全体の「データあり」で代用しない。

| 証拠段階 | 意味 | 次の工程 |
|---|---|---|
| 未確認 | まだ存在・内容を確認できていない | 公式の票・目録・表を調べる |
| 設問・変数確認 | 調査票や辞書に項目がある | 公表表、秘匿、対象自治体での利用可否を確認 |
| 公表目録確認 | 対象表・データ公開の案内がある | 原本を取得し、対象範囲と実数値を点検 |
| 原表内容確認 | 原表の対象・数値・注記を確認した | コード・境界・母集団を照合して正規化 |
| 統合検証済み | 数値・コード・定義・画面・出力を検証した | 国別版の採用指標として提供 |

これは調査台帳の証拠段階であり、runtimeの`documents[].availability`に新しい列挙値を追加する指示ではない。調査票の項目が公表データに含まれるとは限らない。地理情報が記録されていても、その粒度の公開を意味しない。

全数と標本、実査値と補正推計、秘匿と欠測を分ける。標本の自治体推計を街区へ配分しない。加重個票を集計する場合は公式ウェイト・対象母集団・重複条件を適用し、ファイルの行数を総人口としない。匿名化個票は配布条件に従い、ダッシュボードへの原票公開を既定としない。

## 4. 計画主体と統計地域を合わせる

1. 計画責任を持つ地方政府と計画区域を、国・地域型・公式コード・有効期間で確定する。
2. その単位の公式集計表を優先する。統計の部門・郡・地区という名称だけで一致させない。
3. 下位統計区分から再集計する場合は、区域が排他的かつ網羅的に対応する証拠、同年・同定義、分子分母、秘匿・ウェイトの処理を残す。条件を満たさなければ再集計しない。
4. 街区・集落は自治体内の地区診断に利用する。小地域データが豊富でも、法定計画主体の地域を選ぶ操作・見出し・出力を保つ。
5. 対象自治体の値が得られない項目は、その自治体の欠測を示す。上位の参考値は地域・年を明記して別表示する。

対象自治体の網羅率を算出する時は、法定対象の全自治体台帳を分母にする。「取得できた自治体数」を分母にしない。全体台帳がない時は網羅率も未確認とする。機能ごとに必要な指標・表・対象地域を分母として提示し、恣意的な総合点を作らない。

## 5. Temáticoの資料収集へ展開する

[18テーマ候補](research/latin-america-2026/REPORT.md)はOWID、国連国勢調査勧告、SDGの探索分類を基にした本テンプレートの整理案である。OWIDが18テーマを指定したという意味ではない。全国家で必ず18メニューを出す仕様でもない。

最初に法定計画の診断項目と地域の課題を整理する。次に国勢調査の収録と照合し、不足項目から省庁別ソース台帳を作る。例えば学校の立地・定員、医療施設、産業生産、道路状態、災害危険度、事業費、予算執行、計画の承認状態は、人口・住宅センサスだけでは揃わない。

優先順は①法定必須項目、②地域で合意・記録された課題、③人口・水衛生等の基礎診断、④その他の比較候補とする。同じ資料が複数テーマを支える場合はsource単位で一度取得し再利用する。API・CSV・Excelを優先し、REDATAMの公開出力、PDF、画像/OCRへ順に適応する。APIがなければ自動化できないと判断しない。

国際データは国レベルの背景、概念辞書、国内資料への探索入口として使える。国際推計の全国率を地方に適用しない。省庁名・法令・公開先は改編し得るため、資料当時の機関と現在の管理機関を区別する。

比較の前に必ず次を確認する。

- 水道接続、水源の改善、安全に管理された水を区別する。安全な管理には水質・必要時の利用可能性等の条件があり、配管だけで判定しない。[JMP](https://washdata.org/topics/drinking-water)
- 世帯ネット接続、住宅のネット設備、個人のネット利用を区別する。個人利用の年齢・参照期間、固定／モバイル、複数回答もそろえる。
- NBI・多次元貧困・所得貧困、識字・学歴・学力、障害の疾患分類・機能分類を混ぜない。
- 国際比較が成立しない指標も、国内同定義の自治体比較には使える場合がある。国際比較不可を理由に国内の有用な指標を消さない。

## 6. 診断から計画・事業へつなぐ自動化

国別案件に次の根拠連鎖を残す。各関係は根拠のある対応とAIが提案する対応を区別する。

```text
法定計画の要求・地域の課題
    → 必要指標・資料
    → 原表・頁・定義・地域照合
    → 診断の事実・課題仮説
    → 協議で確認された要求・優先順位
    → 事業候補・既存投資との照合
    → 目標・担当・資金・期間の合意
    → 計画草案・承認根拠
    → 実施記録・見直し
```

AIは資料探索、取得、表の変換、比較、根拠付き文章案、現地様式への転記、欠落・不整合検査を進める。本文の事実記述には資料IDと頁・表・抽出位置を持たせる。数値処理で作る指標とAIの文章生成を分け、出典を提示できない断定・因果推論・数値は採用しない。

住民の要求、会議での合意、事業費、目標値、責任主体、財政上の約束、公式承認をAIが創作しない。既存記録の整理と提案草案までは進め、自治体・協議体が判断すべき事項を明示した編集可能な草案を完成させる。CDM、OMPP、RUDCT、PMDという名称・様式・承認経路はドミ共の固有制度として国別に対応付ける。現地判断は計画作成中も見直し時も継続して記録する。

SISMAP型の統合システムがなくても、地方政府、計画機関、財務、議会・公報、監査の公開資料をsource別に収集できる。資料取得状態、計画の承認状態、予算執行、目標達成、公式評価は[計画資料データ契約](PLANNING_DATA_CONTRACT.md)に沿って分ける。

## 7. 実装と納品の境界

現行テンプレートにはWDI・参照境界の初期収集、国別アダプター追加の手順、地域診断・テーマ比較、資料と基礎出力、計画資料の任意契約がある。今回追加したのは制度・国勢調査・不足分野をつなぐ調査手順と20か国の調査台帳である。20か国の国勢調査コネクター、法令自動解釈、各国公式Word様式、自動計画承認は実装済みと報告しない。

国別の最初の完了単位は、制度・公式コードを確認した対象自治体で、採用した統計・原資料・出力が一致する診断基礎資料を作ること。比較的データのある自治体と不足する自治体を含める。その後、国別の全対象自治体へ拡張し、分野資料、参加・事業、計画草案の工程を進める。段階の進展と法定計画の完成は別に報告する。

受入時は対象commit・調査／公開版・境界版・確認日・未検証を記録する。更新は候補版で検証してから反映し、失敗時は最後の正常版を保持する。調査台帳はevidence領域で管理し、設計用profileやruntime schemaへ未対応フィールドを混ぜない。
