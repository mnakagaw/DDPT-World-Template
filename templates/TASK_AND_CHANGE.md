## 差分台帳

| ID | 対応ページ・共通契約 | 現行の動作 | 変更後の動作 | 根拠・国別条件 | データ／保存／操作への影響 | 判断状態・根拠 | 受入ID |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

判断状態は「既存指示内」「国別適応規則内」「提案中」「採用」「見送り」等。採用した人・日付・参照する指示を記す。提案の作成だけで実装への承認を得た扱いにしない。

## 判断の出発点

| 変更例 | 扱い |
|---|---|
| 現地語への翻訳、通貨・単位、正しい制度用語 | 確認済みの国別設定内なら進める |
| 年次データがないため時系列を固定年比較へ変更 | 合意した適応規則内なら進め、理由を記録する |
| 地域選択と指標連動の不具合修正 | 意図された操作に戻す範囲で実装・検証する |
| 各指標の下部へ内部比較の地図・全件表を追加 | 今回の明示指示内。上部配置、分析対象、値の意味を保ち、A35以降で検証する |
| 世界・大陸・広域等の探索区分を採用 | 構成地域・分類出典・比較条件を記録。法定計画主体や承認者を自動付与しない |
| 内部比較クリックを分析対象変更へつなぐ／基礎自治体からさらに細分する | 今回の契約に反する。既存の上部選択を使い、通常の細分停止点を保持する |
| 長い翻訳に合わせた余白・幅の調整 | 情報配置・読みやすさを検証して進める |
| 国別資料区分の名称・順序、既存の投資・財政への接続 | 資料と業務の根拠を残し、既存操作・地域保持・取得済み資料への到達を保って進める |
| ４資料区分を固定の同大カードや独立ページにする | 探索区分だけでは追加の根拠にならない。必要な利用業務と既存導線への影響を具体化する |
| 資料収録状況の地図を公式状態の地図へ変更 | 意味の変更。国別の定義、区分・正確な資料期間・公式根拠、未確認表示とA32を記録する |
| 計画の出力を新規に採用／保留 | 新規導入は資料と業務で判断し、保留時の原資料・整理欄等の代替を作る。既存出力の削除とは区別する |
| 地域診断とテーマ診断の統合、操作の追加 | 共通モデルへの影響を示し、許可範囲外なら判断を得る |
| 分母や順位母集団を変えて値を読み替える | 意味の変更として根拠と判断を記録する |
| 未取得の分野・出力・保存機能を削除する | 新規導入の保留と既存機能の削除を分け、後者は影響を確認する |

## 比較用証拠

- 変更前：commit／URL／地域・指標・期間／表示幅／認証状態／画像
- 変更後：同じ条件の画像と、異なる条件なら理由
- 実操作での差：
- 画面・文書・保存データの互換性：
- 計画資料の原本・頁／表・地域対応・期間・状態・代表値の照合、A27以降の結果：
- 各指標内部比較の構成地域・全件数・期間・単位・出典、上部維持・対象不変・全表印刷、A35以降の結果：
- 取得失敗時に正常版が残る証拠と、再開点のHANDOFF.md：
- 未実施項目：
- 独立レビューの所見と対応：

この台帳はすべての編集に新しい承認を要求するものではない。通常判断を記録し、意図の変更だけを具体的な成果として見えるようにする。

共通UX 0.4 candidateへの記載は、v1.0採用や実装・実利用者の受入完了を意味しない。設計profile schema 0.1と実行dataset schema 0.2を別々に記録する。計画資料の詳細は[計画資料データ契約](../docs/PLANNING_DATA_CONTRACT.md)、追加の実行設定は[実装契約](../docs/IMPLEMENTATION_CONTRACT.md)に従う。
